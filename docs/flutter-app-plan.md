# خطة تطبيق سند بـ Flutter — واجهة الويب نفسها على الجوال

> القرار ومبرراته: [ADR-0023](adr/0023-mobile-app-flutter.md) (يحلّ محل ADR-0018). مرجع المنتج والتصميم: الويب و[ADR-0022](adr/0022-local-first-daily-companion.md).
> المدة المقدّرة: **13 أسبوعاً حتى الإطلاق العام**، بفريق: مطوّرا Flutter، مطوّر خادم (جزئي)، مصمم (جزئي)، مختبِر (من الأسبوع 6).
> البيئة جاهزة على جهاز التطوير: Flutter 3.44.3 / Dart 3.12.2.
> النطاق شرعي فقط منذ [ADR-0024](adr/0024-sharia-only-scope.md): حُذف قسم الصحة والإحالة التلقائية عند الخطر من الخطة والتطبيق.

## 1. المبدأ: «الويب نفسه، بإحساس تطبيق أصلي»

من يفتح سند على الجوال بعد الويب يجب أن يشعر أنه في البيت نفسه:

- **الهوية نفسها:** «سكينة الفجر» — نفس الألوان والخطوط والزوايا والظلال وتدرّج الفجر، والليلي «غسق أزرق» لا أسود.
- **الشاشات نفسها، بالترتيب نفسه:** كل صفحة ويب لها شاشة مقابلة بالمحتوى والتسلسل والنصوص نفسها (الجدول في §4).
- **المكوّنات نفسها:** البطاقة، الزر، شارة الحكم، حلقة التقدّم، كتلة الآيات، عدّاد التسبيح، دائرة الذكر بتمهّل، مخطط المذكّرة، بطاقة المشاركة.
- **ما يختلف عمداً (لصالح الجوال):** شريط تبويبات سفلي بدل القائمة العلوية، إيماءات الرجوع، اهتزاز خفيف عند إتمام العدد،
  تذكير محلي بدل ملف `.ics`، قفل بالبصمة من النظام، تشغيل التلاوة في الخلفية وعلى شاشة القفل، وأيقونة بديلة متحفّظة.

## 2. النطاق

| **الرقية والتحصين** المكتوبة (المجموعات والأدلة) | ودجت «وِرد اليوم» على الشاشة الرئيسية | إدارة المحتوى والخطط |
| **مكتبة التلاوات** + التشغيل في الخلفية | | |
| **الدليل والحجز والمحادثة** + توصياتي | | |
| **الحساب:** الملف، تصدير البيانات، حذف الحساب | | |
| **الدخول:** Google (+ Apple على iOS) — الرفيق يعمل بلا حساب | | |
| **الإشعارات:** تذكير أذكار محلي + إشعارات الخادم (رسائل، حجوزات، توصيات) | | |

**الثوابت (من البنود العشرة):** لا تشخيص ولا وعد بنتيجة ولا تصنيف للمستخدم، لا دفع ولا اشتراك، البيانات الحساسة مشفّرة،

## 5. مصدر واحد للمحتوى والسلامة

**القاعدة:** ممنوع كتابة آية أو ذكر أو نص سلامة داخل كود Dart.

1. **نقل محتوى الرفيق إلى المشترك:** `library.ts`، `programs.ts`، `myths.ts`، `quiz.ts`، `arabic.ts`
   من `frontend/src` إلى `packages/shared/src` (الويب يستوردها عبر `@sanad/shared/*` كما يفعل مع المصحف).
2. **مولّد `packages/shared/scripts/export-dart.mjs`:** يكتب `mobile_flutter/assets/content/*.json`
   (المصحف، الرقية، الأوراد، البرامج، الميزان، الاختبار، نصوص i18n).
3. **فحص في CI:** يعيد التوليد ثم `git diff --exit-code` — أي JSON لا يطابق المصدر يُسقط البناء.
4. **رموز التصميم:** `frontend/scripts/export-tokens.mjs` يقرأ متغيّرات `:root` والليلي من `index.css` ويكتب `lib/theme/tokens.g.dart`.
5. **متجهات التطابق:** `packages/shared/test-vectors/*.json` — أزواج توحيد عربي،
   استعلامات الميزان ونتيجتها المتوقعة، إجابات الاختبار والبرنامج المقترح، وخزنة مذكّرة مشفّرة معروفة يجب أن يفتحها الطرفان.
   يشغّلها Vitest وflutter_test؛ أي اختلاف بين الويب والجوال = اختبار فاشل.

## 7. المراحل ومعايير القبول

### الأسبوع 1 — التأسيس
- إنشاء المشروع بالمعرّف `app.sanad`، RTL، الخطوط، الثيم من الرموز المولَّدة، الوضع الليلي، CI (تحليل + اختبارات + بناء).
- نقل محتوى الرفيق إلى `packages/shared` + المولّدان + متجهات التطابق.
- **القبول:** شاشة تجريبية بألوان وخطوط مطابقة للويب؛ CI يفشل إن عُدّل `quran.ts` دون إعادة التوليد.

### الأسابيع 2–3 — نظام المكوّنات والرفيق بلا حساب
- كل مكوّنات §1 مع اختبارات Golden (فاتح/ليلي، حجم خط كبير، شاشة صغيرة).
- الرئيسية، يومي، البرامج، المرشد، الميزان والاختبار، السكينة (تعمل في وضع الطيران بعد حفظ التلاوات).
- **القبول:** مراجعة جنباً إلى جنب مع لقطات الويب (Playwright) لكل شاشة؛ أول نسخة داخلية للمختبرين.

### الأسابيع 4–5 — الخصوصية والمذكّرة والتذكير
- المذكّرة المشفّرة + البصمة + القفل التلقائي + المخطط.
- الوضع المتحفّظ: أيقونة بديلة، اسم محايد في المهام الأخيرة، خروج سريع.
- بطاقات المشاركة، والتذكير المحلي (صباح/مساء/نوم) بنص محايد «وِرد اليوم».
- **القبول:** خزنة الويب المعروفة في المتجهات تُفتح في Flutter والعكس؛ التذكير يصل والتطبيق مغلق وبلا شبكة.

### الأسابيع 5–7 — الحساب والمحتوى المتصل
- دخول Google/Apple الأصلي، الجلسة (رمز الوصول في الذاكرة، التحديث في التخزين الآمن)، تجديد صامت.
- الرقية والتحصين، المكتبة مع التشغيل في الخلفية والمفضلة.
- **القبول:** 30 دقيقة تلاوة متواصلة بشاشة مقفلة؛ رمز منتهٍ ⇐ تجديد صامت مرة واحدة.

### الأسابيع 7–9 — الدليل والحجز والمحادثة والإشعارات
- الدليل، صفحة المختص، الحجز، حجوزاتي، المحادثة (SignalR)، توصياتي، الحساب (تصدير/حذف)، إشعارات FCM.
- **القبول:** حجز من الدليل حتى قبوله ثم محادثة المختص مع إشعار بالرد؛ حذف الحساب يمسح الجلسة والتذكيرات ورمز الإشعارات.

### الأسابيع 10–11 — الجودة والتجربة المغلقة
- إمكانية الوصول (قارئ الشاشة بالعربية، أحجام الخط، التباين)، الأداء، Sentry، سيناريوهات Maestro، اختبار اختراق.
- تجربة مغلقة (TestFlight + Google Play Internal) لـ 200 مستخدم.
- **الحالة (2026-10-23):**
  - المنجز: الوصول، والحجم، وE2E، واختبار الاختراق، والحِمل.
  - Sentry مستبعَد لصالح Android vitals.
  - التجربة نفسها تنتظر حسابات المتجرين ومفتاح التوقيع. التفاصيل في [flutter-beta-checklist.md](flutter-beta-checklist.md).

### الأسبوعان 12–13 — الإطلاق والانتقال
- إرسال للمتجرين مع ملاحظات المراجِع (لا تشخيص، حذف الحساب داخل التطبيق، Sign in with Apple).
- إطلاق متدرّج 5% ← 20% ← 100%، وتحديث README والمستندات.

| المؤشر | الحد |
|---|---|

| تطابق المحتوى والسلامة | 100% من متجهات §5 تنجح في الطرفين |
| المستخدمون بلا أعطال | ≥ 99.8% |
| ANR في Android | < 0.47% |
| الإقلاع البارد حتى أول تفاعل | ≤ 1.5 ث iPhone، ≤ 2.5 ث Android متوسط |

| حجم التحميل | ≤ 40MB (الخطوط العربية الثلاثة ≈ 1MB) |
| التذكير المحلي | ≥ 99% في وقته، التطبيق مغلق وبلا شبكة |
| السكينة دون إنترنت | تعمل كاملة في وضع الطيران بعد أول حفظ للتلاوات |

## 9. سيناريوهات E2E الإلزامية (Maestro)
1. بدء «أساس التحصين» بلا حساب، إتمام مهام اليوم، إعادة فتح التطبيق ⇐ التقدّم محفوظ.
2. وضع الطيران: يومي والبرامج والسكينة والتلاوات المحفوظة تعمل؛ الباقي برسالة واضحة.
3. إنشاء المذكّرة، قفلها، فتحها بالرمز، والكتابة فيها.
4. الوضع المتحفّظ يغيّر الأيقونة والاسم، والخروج السريع يعيد للشاشة الرئيسية للنظام.
5. دخول Google ⇐ حجز ⇐ محادثة ⇐ إشعار بالرد.
6. حذف الحساب يمسح كل شيء محلياً وفي الخادم.
7. لا عنصر دفع أو اشتراك في أي شاشة.

## 10. المخاطر

| الخطر | المعالجة |
|---|---|
| انحراف المحتوى أو منطق السلامة بين الويب والجوال | مصدر واحد في `packages/shared` + مولّد + متجهات تطابق في CI |
