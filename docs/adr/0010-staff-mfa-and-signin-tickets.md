# ADR-0010: 2FA إلزامي للأدوار الإدارية، ومراحل دخول بتذاكر قصيرة الأجل
التاريخ: 2026-09-23
الحالة: مقبول

## السياق
المرجع (§4.10) يطلب تفعيل 2FA فور منح أي دور حساس وعدم السماح بأي عملية إدارية قبل تفعيله فعلياً.

## القرار
- الأدوار الحساسة: Coordinator, ContentManager, PrivacySecurityOfficer, ClinicalSupervisor, SystemAdmin.
- منح دور حساس: `TwoFactorEnabled = true` + إبطال كل جلسات المستخدم فوراً.
- الدخول متعدد المراحل: عند الحاجة لتغيير كلمة مرور مؤقتة أو إعداد/إدخال 2FA، يُعاد **Ticket** معتم (10 دقائق، 5 محاولات، مخزّن كبصمة) بدلاً من الرموز.
- الرمز النهائي يحمل `amr`: `pwd` / `otp` / `google` / `mfa`. **كل Endpoint وأمر إداري يتطلب `amr=mfa`** — مفروض في طبقتين: Policy في الـ API، و`RequireRoles(RequireMfa = true)` في الـ Pipeline (مفحوص بالانعكاس على كل الطلبات).
- إبطال الرموز: قائمة `jti` + "إبطال شامل قبل لحظة X" بدقة الميلي ثانية (claim `iat_ms`)، في Redis إن وُجد.
- رموز التحديث: بصمة SHA-256 فقط، تدوير عند كل استخدام، وإعادة استخدام رمز مُدوَّر تبطل كل جلسات المستخدم.

## الأثر
- لا رموز استرداد (Recovery Codes) في هذا الإصدار: فقدان تطبيق المصادقة يُعالَج بإجراء إداري موثَّق من `SystemAdmin`.
