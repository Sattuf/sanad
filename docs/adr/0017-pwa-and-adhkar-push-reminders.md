# ADR-0017: تطبيق الجوال (PWA) وتذكير الأذكار بإشعارات Web Push
التاريخ: 2026-09-30
الحالة: مقبول

## السياق
المستخدم يريد سند على جواله كتطبيق، وتذكيراً بأذكار الصباح والمساء والنوم في وقتها حتى والتطبيق مغلق.
ملف التقويم (ICS) يغطي من لا حساب له، لكنه لا يفتح الورد مباشرة في كل الأجهزة ولا يتزامن مع الحساب.

## القرار
- **تطبيق ويب قابل للتثبيت (PWA)** بدل تطبيقَي متجر منفصلين: `manifest.webmanifest` عربي (`dir: rtl`) بأيقونات
  عادية وقابلة للقص واختصارات للأوراد، وعامل خدمة يدوي بلا مكتبات (`public/sw.js`):
  - لا يخزّن أي طلب إلى الـ API ولا أي طلب من أصل آخر (بيانات شخصية).
  - التنقّل: الشبكة أولاً ثم آخر نسخة من الواجهة؛ ملفات `/assets/` المجزّأة تُخزَّن عند التثبيت ⇐ الأذكار تعمل دون اتصال.
  - الإشعار لا يفتح إلا مساراً داخلياً (`/…`)؛ أي رابط خارجي في الحمولة يُستبدل بـ `/ruqyah`.
- **Web Push بمعيار المتصفح (RFC 8030 + VAPID)** عبر `Lib.Net.Http.WebPush` (MIT): لا حساب مزوّد ولا Firebase SDK؛
  الحمولة مشفّرة للجهاز (aes128gcm). هذا لا يمس ADR-0009 — قناة FCM العامة هناك تبقى معطّلة.
- **جدول `ReminderDevices`**: عنوان الإشعار + مفتاحا التشفير + منطقة IANA الزمنية + ثلاثة أوقات (null = متوقف) +
  تاريخ آخر إرسال لكل وقت. العنوان فريد: المتصفح نفسه إن سُجّل بحساب آخر انتقل إليه. حد أقصى 10 أجهزة لكل حساب.
- **مهمة `AdhkarReminderJob` كل دقيقة**: ترسل ما حان بتوقيت صاحبه خلال نافذة 30 دقيقة، مرة في اليوم لكل وقت
  (نافذة وقت قبل منتصف الليل تُنسب لليوم السابق). 404/410 من خدمة الدفع ⇐ حذف الجهاز. الفشل المؤقت يُعاد في الدقيقة التالية.
- **منع SSRF**: الخادم يرسل طلباً إلى عنوان يقدّمه المستخدم، فلا يُقبل إلا HTTPS على المنفذ الافتراضي لخدمات الدفع
  المعروفة (`fcm.googleapis.com`، `push.services.mozilla.com`، `push.apple.com`، `notify.windows.com`)، ويُعاد الفحص قبل كل إرسال،
  ولا تحويلات (AllowAutoRedirect=false).
- **نص الإشعار عام وثابت** (اسم الورد فقط) — لا بيانات شخصية في أي إشعار.
- الأجهزة تُحذف مع حذف الحساب وتُضمَّن في تصدير البيانات.
- iPhone: الإشعارات لتطبيق سند المثبّت فقط (iOS 16.4+)؛ الواجهة ترشد إلى «إضافة إلى الشاشة الرئيسية».

## الإعداد
```
WebPush:Enabled=true
WebPush:PublicKey=<base64url لنقطة P-256 غير مضغوطة (65 بايت)>
WebPush:PrivateKey=<base64url للمفتاح الخاص (32 بايت)>   # سرّ — في Key Vault/user-secrets فقط
WebPush:Subject=mailto:<بريد التواصل>
```
توليد الزوج مرة واحدة (Node):
```
node -e 'const k=require("crypto").generateKeyPairSync("ec",{namedCurve:"prime256v1"}).privateKey.export({format:"jwk"});console.log(Buffer.concat([Buffer.from([4]),Buffer.from(k.x,"base64url"),Buffer.from(k.y,"base64url")]).toString("base64url"),k.d)'
```
تغيير المفاتيح يُبطل تسجيل كل الأجهزة (يعيد المستخدمون التفعيل). `StartupGuards` يرفض الإقلاع إن فُعّل بلا مفاتيح.
بلا إعداد: `GET /public/reminders/push-config` يعيد `enabled=false` فلا تظهر الإشعارات، ويبقى ملف التقويم.

## الأثر
- واجهة API: `GET /public/reminders/push-config`، و`/me/reminders/devices` (GET)، `/me/reminders/device` (PUT)،
  `/me/reminders/device/remove` و`/me/reminders/device/test` (POST).
- عامل الخدمة يُسجَّل في الإنتاج فقط (وفي التطوير عند تفعيل الإشعارات)، ويجب أن يُخدم `sw.js` من جذر الموقع.
