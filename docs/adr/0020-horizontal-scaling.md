# ADR-0020: جاهزية التوسّع الأفقي لـ 100 ألف مستخدم
التاريخ: 2026-10-01
الحالة: مقبول — يكمّل ADR-0002 وADR-0009 وADR-0017 و`references/11` §11.8

## السياق
الهدف 100 ألف مستخدم مسجّل وذروات عند أوقات الأذكار، أي أكثر من نسخة API خلف موزّع حمل. أربع نقاط في الكود كانت تمنع ذلك:
1. `AdhkarReminderJob` يحمّل **كل** الأجهزة كل دقيقة ويرسل بالتتابع.
2. المهام الخلفية (Outbox، التذكير، انتهاء التوثيق) تعمل في **كل** نسخة ⇐ تكرار إشعارات ورسائل.
3. الملفات على قرص الخادم — لا تُشارك بين النسخ، والصوت كله يمر عبر الـ API.
4. Redis اختياري — وهو Backplane لـ SignalR وذاكرة مشتركة لإبطال الرموز ورموز الدخول المؤقتة.
وأيضاً: Outbox يحمّل كل الرسائل المعلّقة في الذاكرة ثم يأخذ دفعة.

## القرار
- **قفل لكل مهمة (`IJobLock`)**: قفل استشاري في PostgreSQL (`pg_try_advisory_lock`) على اتصال مستقل طوال العمل.
  كل النسخ تحاول كل دورة، وواحدة فقط تعمل والباقي يتخطى بلا انتظار. سقوط النسخة يغلق الجلسة فيحرّر القفل تلقائياً.
  SQLite (تطوير/اختبار): قفل داخل العملية. اخترناه بدل عملية Worker منفصلة لأنه بلا بنية إضافية، ويبقي النشر صورة واحدة.
- **`ReminderDevice.NextDueAtUtc` مفهرس**: أقرب لحظة UTC لوقت لم يُرسل بعد، يُحدَّث عند الجدولة وبعد كل دورة
  (وقت في فجوة التوقيت الصيفي يُزاح ساعة). المهمة تجلب المستحق فقط بصفحات 500 مرتبة بالمعرّف، وترسل بتوازٍ محدود
  (`WebPush:MaxParallelSends`، افتراضياً 32)، وتحسب الصفوف القديمة مرة واحدة.
- **Outbox**: الدفعة تُختار في القاعدة (`ORDER BY … LIMIT`) على الفهرس الموجود.
- **تخزين كائنات متوافق مع S3** (`Storage:Provider=S3`): Amazon S3 وCloudflare R2 وMinIO. الحاوية خاصة دائماً.
  الصوت المنشور وتلاوات الآيات المخزّنة **تُحوَّل (302) إلى CDN** (`Storage:S3:PublicBaseUrl`)، أو لرابط موقّع لـ 6 ساعات إن لم يوجد CDN.
  فقط البادئات العامة (`library-audio/`، `recitation-cache/`) تمر عبر CDN. مستندات التوثيق روابط موقّعة قصيرة دائماً،
  والمعاينة غير المنشورة تُبث عبر الـ API.
- **حدود المعدل مشتركة عبر Redis**: عدّاد بنافذة ثابتة لكل (سياسة، مفتاح، نافذة) يُزاد ذرّياً بسكربت Lua
  (`INCRBY` + `PEXPIRE`)، فالحد في `RateLimiting:*` هو الحد الكلي لكل النسخ معاً. مفاتيح Redis تحمل بصمة SHA-256 مختصرة
  لا عنوان IP ولا معرّف المستخدم. **إن سقط Redis لا تُفتح البوابة**: كل نسخة تطبّق الحد نفسه محلياً حتى يعود
  (حماية رصيد SMS لـ OTP). بلا Redis (تطوير/نسخة واحدة) يبقى المحدِّد المحلي كما كان.
- **حراسات الإقلاع في الإنتاج**: Redis وتخزين S3 إلزاميان، والاستثناء الوحيد `Deployment:SingleInstance=true` معلَن صراحةً.

## القياس
على PostgreSQL 16 محلي، مع مرسل وهمي (يقيس مسار القاعدة لا الشبكة):

| الحالة | الزمن |
|---|---|
| دقيقة فيها 50,000 جهاز مستحق | 7.8 ث |
| دقيقة خاملة مع 100,000 جهاز ولا شيء مستحق | 19 ms (كانت: قراءة 100 ألف صف كل دقيقة) |

الإرسال الفعلي محكوم بزمن خدمات الدفع: ~100ms لكل إشعار مع 32 متوازياً ≈ 300 إشعار/ث.
على الجوال التذكير محلي (ADR-0023)، فهذا المسار لمستخدمي متصفح الويب فقط.

## الإعداد (إنتاج)
```
ConnectionStrings:Redis=<redis>
Storage:Provider=S3
Storage:S3:Bucket=sanad-media
Storage:S3:ServiceUrl=https://<account>.r2.cloudflarestorage.com   # فارغ لـ Amazon S3
Storage:S3:Region=auto                                              # أو منطقة AWS
Storage:S3:AccessKey / SecretKey                                    # أو دور IAM للخادم
Storage:S3:PublicBaseUrl=https://media.sanad.app                    # CDN أمام البادئات العامة فقط
WebPush:MaxParallelSends=32
```
ترحيل الملفات الحالية: نسخ مجلد `Storage:RootPath` إلى الحاوية بالمفاتيح نفسها (مثل `aws s3 sync storage/ s3://sanad-media/`).

## الاختبار
القفل بين نسختين، وكل مسار المهام على PostgreSQL الحقيقي (Testcontainers في CI، أو `SANAD_TEST_PG_CONNECTION`).
ذهاب وإياب S3 مع رفع ← نشر ← توجيه ← معاينة عبر الـ API (محاكي moto في CI عبر Testcontainers، أو `SANAD_TEST_S3_ENDPOINT`).
حدود المعدل على Redis حقيقي (Testcontainers في CI، أو `SANAD_TEST_REDIS`): نسختان تتقاسمان العدّاد، وتجدّد النافذة،
وحد OTP عبر نسختين من الـ API، والرجوع لحد محلي عند سقوط Redis.
