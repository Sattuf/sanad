# جاهزية الخادم للإنتاج (100 ألف مستخدم)

قائمة ما يلزم الخادم قبل الإطلاق العام، أياً كان العميل (الويب أو تطبيق Flutter). نُقلت من خطة تطبيق الجوال السابقة
لأنها تخص الخادم لا التطبيق. القرار المعماري: [ADR-0020](adr/0020-horizontal-scaling.md).

**افتراضات الحمل** (تُراجع بالأرقام الفعلية بعد التجربة المغلقة): 100 ألف مسجَّل · 20–25 ألف نشط يومياً ·
ذروة متزامنة ~3,000 عند الصباح والمساء وبعد العشاء · الصوت هو أكبر استهلاك شبكة (~100GB يومياً إن استمع 20 ألفاً 5 دقائق).

مشاكل كانت في الكود ويجب حلها قبل الإطلاق — **حُلّت الأربع** ([ADR-0020](adr/0020-horizontal-scaling.md)):

| # | المشكلة | الحل | القبول |
|---|---|---|---|
| 1 ✅ | `AdhkarReminderJob` يحمّل **كل** الأجهزة كل دقيقة ويرسل بالتتابع | `NextDueAtUtc` مفهرس، صفحات 500، إرسال متوازٍ (32) | **قيس: 50 ألف مستحق 7.8 ث؛ دقيقة خاملة مع 100 ألف 19ms** |
| 2 ✅ | المهام الخلفية تعمل في **كل** نسخة API ⇐ تكرار إرسال | قفل `pg_try_advisory_lock` لكل مهمة؛ Outbox يختار دفعته في القاعدة | مختبَر: نسختان ⇐ واحدة تعمل |
| 3 ✅ | `LocalFileStorage` على قرص الخادم | تخزين متوافق مع S3 (S3/R2/MinIO) + توجيه الصوت المنشور إلى **CDN**؛ روابط موقّعة للخاص | مختبَر على خادم S3: المنشور ⇐ 302 إلى CDN |
| 4 ✅ | Redis اختياري | **إلزامي** في الإنتاج مع S3 (حراسة إقلاع)، إلا `Deployment:SingleInstance=true` صراحةً | الإقلاع يُرفض بدونهما |

وبقية التجهيز:
- [ ] PostgreSQL مُدار + PgBouncer، فهارس مراجَعة بـ `EXPLAIN` لأعلى 20 استعلاماً، نسخ احتياطي واختبار استعادة فعلي.
- [ ] API عديمة الحالة بنسختين على الأقل خلف موزّع حمل، توسّع تلقائي على CPU، جلسات لاصقة لـ SignalR (أو خدمة SignalR مُدارة).
- [ ] حدود معدل مزدوجة (IP + حساب)، وسقف يومي لتكلفة SMS مع تنبيه (100 ألف مستخدم = خطر استنزاف OTP حقيقي).
      ✅ الحدود مشتركة بين النسخ عبر Redis، وتعود محلياً إن سقط (ADR-0020). ← بقي: السقف اليومي لتكلفة SMS مع تنبيه.
- [ ] OpenTelemetry: لوحات p95 والأخطاء لكل نقطة، تنبيهات، Correlation-Id من التطبيق حتى قاعدة البيانات.
- [ ] **توافق الإصدارات**: لا كسر لـ `/api/v1` ما دام إصدار تطبيق قديم يستخدمه؛ الحقول الجديدة اختيارية؛ الإجبار على التحديث عبر `min-version` فقط.
- [ ] الامتثال: سياسة خصوصية محدّثة، اتفاقيات معالجة مع FCM وSentry ومزود SMS، ومراجعة قانون حماية البيانات في بلد الإطلاق (مثل PDPL السعودي).
