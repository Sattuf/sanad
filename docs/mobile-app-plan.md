# خطة تطبيق سند للجوال — React Native (Expo) لـ 100 ألف مستخدم

> القرار التقني ومبرراته: [ADR-0018](adr/0018-mobile-app-react-native.md).
> المدة: **12 أسبوعاً حتى الإطلاق العام**، بفريق: مطوّرا جوال، مطوّر خادم، مصمم (جزئي)، مختبِر (من الأسبوع 6).

## 1. الهدف والنطاق

**الهدف:** تطبيق أصلي في App Store وGoogle Play للمستفيد، يتحمّل 100 ألف مستخدم مسجَّل مع ذروات أوقات الأذكار.

| داخل الإصدار 1.0 (المستفيد) | الإصدار 1.1 | يبقى على الويب فقط |
|---|---|---|
| الدخول: بريد، هاتف OTP، Google، Apple | بوابة المختص (الحجوزات، الملاحظة، التوصية) | بوابة التنسيق |
| الرقية والأوراد والأذكار + التذكير المحلي | قفل التطبيق بالبصمة | الإدارة والأدوار (2FA) |
| مكتبة التلاوات + التشغيل في الخلفية | ودجت الشاشة الرئيسية للورد | إدارة المحتوى |
| الدليل والحجز والمحادثة | | |
| توصياتي، قسم الصحة والطمأنينة | | |
| الحساب: الخصوصية، تصدير البيانات، حذف الحساب | | |
| الإشعارات (رسائل، حجوزات، توصيات) | | |

## 2. الحزمة التقنية

| الطبقة | الاختيار |
|---|---|
| الإطار | Expo SDK (أحدث مستقر) + React Native (المعمارية الجديدة) + TypeScript strict |
| التنقل | Expo Router (مسارات ملفات، روابط عميقة جاهزة) |
| حالة الخادم | TanStack Query + حفظ دائم عبر `react-native-mmkv` (للفهرس والدليل فقط، **لا** للرسائل والتوصيات) |
| حالة العميل | Zustand |
| النماذج | React Hook Form + Zod (المخططات من `packages/shared`) |
| التصميم | NativeWind (Tailwind) بنفس رموز الألوان والمسافات الحالية |
| الحركة | Reanimated + Moti، مع احترام «تقليل الحركة» |
| القوائم | FlashList (الدليل، المكتبة، المحادثات) |
| الصوت | `react-native-track-player` — خلفية، شاشة القفل، سماعات البلوتوث |
| الخطوط | `expo-font`: IBM Plex Sans Arabic، Amiri، Amiri Quran |
| RTL واللغة | `I18nManager.forceRTL` + `expo-localization` + i18next (نصوص مشتركة) |
| التخزين الآمن | `expo-secure-store` (رمز التحديث فقط) |
| الإشعارات | `expo-notifications`: محلية للأذكار، ورموز FCM/APNs الأصلية لإشعارات الخادم |
| الدخول الاجتماعي | `@react-native-google-signin/google-signin` + `expo-apple-authentication` |
| الوقت الفعلي | `@microsoft/signalr` (نفس الويب) |
| حماية الشاشة | `expo-screen-capture` على المحادثة والتوصيات |
| الأعطال والأداء | `@sentry/react-native` مع حذف الأجسام والنصوص والترويسات |
| الاختبار | Jest + React Native Testing Library + **Maestro** للـ E2E |
| البناء والنشر | EAS Build + EAS Submit + EAS Update (إصلاحات JS فورية) |

## 3. هيكل المستودع

```
sanad/
├── package.json                 npm workspaces: frontend, mobile, packages/*
├── packages/shared/             ← يُستخرج من frontend/src (لا كود جديد)
│   ├── api/                     types.ts، client-core.ts (fetch + تجديد الرمز + ApiError + التقاط الطوارئ)
│   ├── safety/                  كشف ترويسة/حقل الطوارئ، نصوص الإحالة
│   ├── schemas/                 مخططات Zod
│   ├── content/                 ruqyah، health، quran (نص مطابق — ADR-0016)
│   └── i18n/ar.ts
├── frontend/                    الويب — يستورد من @sanad/shared
├── mobile/
│   ├── app/                     Expo Router: (auth)/ (tabs)/ ruqyah/ library/ directory/ booking/ chat/ account/
│   ├── src/components/          نظام التصميم الأصلي
│   ├── src/platform/            secure-store، notifications، audio، auth
│   ├── app.config.ts            المعرّف app.sanad، الأذونات، الروابط
│   └── .maestro/                سيناريوهات E2E
└── src/                         الخادم (.NET)
```
**قاعدة:** أي منطق لا يخص العرض يعيش في `packages/shared` ويُختبر مرة واحدة. ممنوع نسخ نص قرآني أو دعاء داخل `mobile/`.

## 4. المراحل ومعايير القبول

### الأسبوع 1 — التأسيس
- [ ] حسابا Apple Developer وGoogle Play (حساب **منظمة** بـ D-U-N-S لتجنب شرط 12 مختبِراً × 14 يوماً للحساب الشخصي).
- [ ] إنشاء `packages/shared` بنقل الملفات من `frontend/src` وتحديث الاستيرادات؛ **الويب يمر بكل اختباراته دون تغيير**.
- [ ] مشروع Expo، EAS، بيئات (dev/staging/prod)، Sentry، CI على كل PR (typecheck، lint، jest).
- [ ] المصمم: تحويل الهوية الحالية إلى شاشات أصلية (تبويبات، رؤوس، أوراق سفلية) في Figma.

**القبول:** `npm test` للويب والحزمة المشتركة أخضر · بناء تطوير يعمل على جهازين حقيقيين بالعربية RTL.

### الأسابيع 2–4 — الأساس والسلامة أولاً
- [ ] نظام التصميم: أزرار، حقول، بطاقات، شارة التوثيق، **شريط الطوارئ** (أول مكوّن يُبنى ويُختبر)، تذييل الإخلاء الإداري.
- [ ] الدخول: بريد، هاتف + OTP + CAPTCHA، Google وApple أصليان (خادم: `POST /auth/google/native` و`POST /auth/apple` بالتحقق من ID Token).
- [ ] الجلسة: رمز الوصول في الذاكرة، رمز التحديث في Secure Store، نفس قواعد ADR-0014 (429 لا يُخرج المستخدم).
- [ ] شاشة «حدّث التطبيق» من `GET /public/app/min-version` (خادم).
- [ ] التبويبات: الرئيسية، الرقية، المكتبة، الدليل، حسابي.

**القبول:** الدخول بالطرق الأربع ينجح · إشارة خطر في أي استجابة ⇐ شريط الطوارئ خلال أقل من ثانية حتى لو فشل الطلب · Maestro: سيناريو الدخول والطوارئ أخضر.

### الأسابيع 4–7 — الميزات
- [ ] الرقية والأوراد بنفس المحتوى المشترك، وتقدّم الورد متزامن مع الحساب.
- [ ] **التذكير المحلي**: الصباح/المساء/النوم، يعمل بلا شبكة، نص عام، النقر يفتح الورد. لا تسجيل للجوال في `ReminderDevices`.
- [ ] المكتبة: تصفح، مفضلة، مشاركة، تشغيل في الخلفية مع شاشة القفل، تحميل للاستماع بلا اتصال (اختياري للمستخدم).
- [ ] الدليل (FlashList + بحث + فلاتر)، الحجز مع `Idempotency-Key`، المحادثة عبر SignalR مع إعادة اتصال.
- [ ] توصياتي، الصحة والطمأنينة، الحساب (الخصوصية، تصدير، **حذف الحساب من داخل التطبيق** — شرط Apple).
- [ ] إشعارات الخادم: تسجيل رمز الجهاز (`PUT /me/push-devices`)، قناة FCM HTTP v1 في `CompositeNotificationDispatcher`، النقر يفتح المسار الصحيح.

**القبول:** كل شاشة 1.0 مكتملة مع حالة تحميل وخطأ وفراغ · سيناريوهات Maestro السبعة في §7 خضراء على Android وiOS.

### الأسابيع 5–9 — تجهيز الخادم لـ 100 ألف (بالتوازي، مطوّر الخادم)
تفاصيلها في §6. **لا إطلاق قبل اكتمالها.**

### الأسابيع 8–10 — الجودة والتجربة المغلقة
- [ ] TestFlight + Play Closed Testing لـ 100–300 مستخدم حقيقي.
- [ ] الأداء: قياس الإقلاع والذاكرة والتمرير على Android متوسط (ذاكرة 4GB) وiPhone 11.
- [ ] الوصولية: تسميات عربية لـ VoiceOver/TalkBack، تكبير الخط حتى 200% دون كسر.
- [ ] **اختبار اختراق** خارجي للتطبيق والـ API (بيانات صحية/دينية حساسة).
- [ ] اختبار حمل k6 بثلاثة أضعاف الذروة المتوقعة (§6).

**القبول:** جدول §5 أخضر · لا ثغرة حرجة/عالية مفتوحة · لا عطل متكرر في Sentry.

### الأسبوعان 11–12 — الإطلاق المتدرّج
- [ ] صفحات المتجر بالعربية، App Privacy وData safety، تصنيف العمر، حساب تجريبي وملاحظة للمراجِع («لا تشخيص ولا علاج»).
- [ ] Google Play: نشر متدرّج 10% ← 50% ← 100%. App Store: Phased Release على 7 أيام.
- [ ] شرط التوسيع في كل درجة: الجلسات بلا أعطال ≥ 99.8%، أخطاء API < 0.5%، p95 ضمن الحد.
- [ ] مناوبة وتنبيهات مفعّلة طوال أسبوع الإطلاق.

## 6. الخادم لـ 100 ألف مستخدم

**افتراضات الحمل** (تُراجع بالأرقام الفعلية بعد التجربة المغلقة): 100 ألف مسجَّل · 20–25 ألف نشط يومياً ·
ذروة متزامنة ~3,000 عند الصباح والمساء وبعد العشاء · الصوت هو أكبر استهلاك شبكة (~100GB يومياً إن استمع 20 ألفاً 5 دقائق).

مشاكل حالية في الكود يجب حلها قبل الإطلاق:

| # | المشكلة الحالية | الحل | القبول |
|---|---|---|---|
| 1 | `AdhkarReminderJob` يحمّل **كل** الأجهزة كل دقيقة ويرسل بالتتابع | الجوال صار محلياً؛ للويب: استعلام بالأجهزة المستحقة فقط + فهرس + إرسال بالتوازي المحدود | تشغيل بـ 50 ألف جهاز < 20 ث |
| 2 | المهام الخلفية (التذكير، Outbox، التحقق) تعمل في **كل** نسخة API ⇐ تكرار إرسال | عملية Worker منفصلة، أو قفل `pg_advisory_lock`، و`FOR UPDATE SKIP LOCKED` في Outbox | 3 نسخ API ⇐ صفر تكرار |
| 3 | `LocalFileStorage` على قرص الخادم — لا يعمل مع أكثر من نسخة | تخزين كائنات (S3/Azure Blob) + **CDN** للصوت وصور المكتبة؛ روابط موقّعة قصيرة للملفات الخاصة | 95% من طلبات الصوت من CDN |
| 4 | Redis اختياري | **إلزامي** في الإنتاج: Cache للدليل والمكتبة، Backplane لـ SignalR، إبطال الرموز، حدود المعدل | سقوط نسخة لا يُخرج المستخدمين |

وبقية التجهيز:
- [ ] PostgreSQL مُدار + PgBouncer، فهارس مراجَعة بـ `EXPLAIN` لأعلى 20 استعلاماً، نسخ احتياطي واختبار استعادة فعلي.
- [ ] API عديمة الحالة بنسختين على الأقل خلف موزّع حمل، توسّع تلقائي على CPU، جلسات لاصقة لـ SignalR (أو خدمة SignalR مُدارة).
- [ ] حدود معدل مزدوجة (IP + حساب)، وسقف يومي لتكلفة SMS مع تنبيه (100 ألف مستخدم = خطر استنزاف OTP حقيقي).
- [ ] OpenTelemetry: لوحات p95 والأخطاء لكل نقطة، تنبيهات، Correlation-Id من التطبيق حتى قاعدة البيانات.
- [ ] **توافق الإصدارات**: لا كسر لـ `/api/v1` ما دام إصدار تطبيق قديم يستخدمه؛ الحقول الجديدة اختيارية؛ الإجبار على التحديث عبر `min-version` فقط.
- [ ] الامتثال: سياسة خصوصية محدّثة، اتفاقيات معالجة مع FCM وSentry ومزود SMS، ومراجعة قانون حماية البيانات في بلد الإطلاق (مثل PDPL السعودي).

## 7. سيناريوهات E2E الإلزامية (Maestro، على كل إصدار)
1. نص فيه إشارة خطر ⇐ شريط الطوارئ فوراً، وزر الاتصال يفتح المتصل.
2. توصية فيها «خذ 500 ملغ» تُرفض برسالة الفلتر (عند وصول بوابة المختص في 1.1).
3. لا مسار يصل إلى ملاحظة الحالة الخاصة، حتى برابط عميق مباشر.
4. حذف الحساب يمسح الرمز المخزّن ويلغي التذكيرات المحلية ويلغي رمز الإشعارات في الخادم.
5. لا عنصر دفع أو اشتراك في أي شاشة.
6. وضع الطيران: الأذكار والرقية والمقاطع المحمّلة تعمل؛ الباقي برسالة واضحة.
7. رمز منتهٍ ⇐ تجديد صامت مرة واحدة؛ 429 لا يُخرج المستخدم.

## 8. المخاطر

| الخطر | المعالجة |
|---|---|
| انحراف منطق السلامة بين الويب والجوال | `packages/shared` + اختبارات مشتركة + مراجعة إلزامية لأي PR يلمسه |
| رفض Apple (4.8 الدخول الاجتماعي، 5.1.1 حذف الحساب، 1.4.1 المحتوى الصحي) | Sign in with Apple من البداية، حذف داخل التطبيق، ملاحظة «لا تشخيص» للمراجِع |
| ذروة الأذكار تُسقط الخادم | التذكير المحلي على الجوال + اختبار حمل بـ 3× الذروة |
| فاتورة الصوت والـ SMS | CDN، سقف OTP يومي وتنبيه تكلفة |
| تسرب بيانات حساسة في السجلات أو تقارير الأعطال | `beforeSend` يحذف النصوص، مراجعة دورية، لا سجلات لأجسام الطلبات |
| إصلاح عاجل بعد الإطلاق | EAS Update لإصلاحات JS خلال ساعات؛ بناء أصلي جديد للباقي |
