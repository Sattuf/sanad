# خطة تطبيق سند للجوال (iOS + Android)

> القرار التقني ومبرراته: [ADR-0018](adr/0018-mobile-app-capacitor.md).
> المدة المستهدفة: **4 أسابيع إلى الإرسال للمتجرين** + أسبوع احتياطي للمراجعة.

## 1. الهدف في سطر
تطبيق سند في App Store وGoogle Play، يعطي **كل** ما في الويب اليوم، مع ثلاث ميزات أصلية تبرّر وجوده كتطبيق:
تذكير أذكار محلي دقيق، جلسة تبقى بعد إغلاق التطبيق، وتشغيل التلاوة في الخلفية.

## 2. الحزمة التقنية

| الطبقة | الاختيار | ملاحظة |
|---|---|---|
| الحاوية الأصلية | Capacitor (آخر إصدار مستقر) | يغلّف `frontend/dist` كما هو |
| الواجهة | React 18 + TS + Vite + Tailwind + Framer Motion | **بلا تغيير** |
| الحالة والبيانات | TanStack Query + Zustand + Zod | بلا تغيير |
| التخزين الآمن | `@aparajita/capacitor-secure-storage` (Keychain/Keystore) | رمز التحديث فقط |
| الإشعارات المحلية | `@capacitor/local-notifications` | أذكار الصباح/المساء/النوم |
| الدخول الخارجي والروابط | `@capacitor/browser` + `@capacitor/app` (deep links) | Google، وفتح الروابط الخارجية |
| المشاركة | `@capacitor/share` + `@capacitor/filesystem` | بدل `navigator.share` لصورة الدعاء |
| مظهر النظام | `@capacitor/status-bar`، `@capacitor/splash-screen`، `@capacitor/haptics` | |
| خصوصية الشاشة | `@capacitor-community/privacy-screen` | إخفاء المحتوى في مبدّل التطبيقات |
| الصوت في الخلفية | `<audio>` الحالي + `UIBackgroundModes: audio` + Media Session | يُستبدل بإضافة أصلية **فقط** إن فشل معيار §5 |
| الأيقونات وشاشة البداية | `@capacitor/assets` | من `public/icons` الحالية |
| الأعطال | `@sentry/capacitor` مع حذف أي جسم طلب أو نص مستخدم | بلا بيانات شخصية |
| البناء والنشر | GitHub Actions + fastlane (iOS على macOS، Android على Ubuntu) | TestFlight + Play Internal |

## 3. الهيكل المضاف

```
frontend/
├── capacitor.config.ts          appId: app.sanad، webDir: dist، بلا server.url في الإنتاج
├── ios/  android/               مولّدة من Capacitor وتُرفع للمستودع
└── src/lib/platform/
    ├── index.ts                 isNative()، واجهة موحّدة
    ├── session-storage.ts       ويب: sessionStorage | أصلي: Keychain/Keystore
    ├── reminders.ts             ويب: Web Push (push.ts) | أصلي: إشعارات محلية
    ├── auth-redirect.ts         ويب: window.location | أصلي: Browser + deep link
    ├── share.ts                 ويب: navigator.share | أصلي: Share + Filesystem
    └── links.ts                 الروابط الخارجية ← متصفح النظام دائماً
```
**قاعدة:** لا ملف في `features/` يستورد `@capacitor/*` مباشرة. كل شيء عبر `lib/platform` — هكذا يبقى الويب سليماً واختباراته كما هي.

## 4. المراحل (كل مرحلة لا تنتهي إلا بمعايير قبولها)

### المرحلة 0 — التجهيز (يومان، تبدأ فوراً وبالتوازي)
- [ ] حساب Apple Developer (99$/سنة) وGoogle Play Console (25$ مرة واحدة).
- [ ] **Google Play للحساب الشخصي الجديد يشترط اختباراً مغلقاً بـ 12 مختبِراً لمدة 14 يوماً متصلة** قبل النشر العام —
      ابدأه في الأسبوع الأول، أو سجّل حساب منظمة (يحتاج D-U-N-S) لتجاوزه.
- [ ] حجز المعرّف `app.sanad` على المنصتين، ونطاق للروابط العامة (`apple-app-site-association` و`assetlinks.json`).
- [ ] رابط سياسة الخصوصية العام وصفحة حذف الحساب (موجودة — ADR-0005) بروابط ثابتة.

**القبول:** الحسابات مفعّلة، والمعرّف محجوز، والاختبار المغلق في Play بدأ عدّاده.

### الأسبوع 1 — الهيكل يعمل على جهاز حقيقي
- [ ] `npx cap init` + منصتا iOS وAndroid، بناء `npm run build && npx cap sync`.
- [ ] `VITE_API_BASE_URL` لكل بيئة؛ إضافة `capacitor://localhost` و`https://localhost` إلى `Frontend:AllowedOrigins`.
- [ ] تعطيل تسجيل `sw.js` داخل التطبيق (`isNative()`)، وإخفاء دعوة «أضف إلى الشاشة الرئيسية».
- [ ] المناطق الآمنة (`env(safe-area-inset-*)`) والنوتش، شريط الحالة بلون السمة، زر الرجوع في Android يتبع الموجّه.
- [ ] الأيقونات وشاشة البداية بالهوية الحالية.
- [ ] الروابط الخارجية تفتح في متصفح النظام، لا داخل التطبيق.

**القبول:** كل الشاشات تعمل على iPhone وAndroid متوسط (مثل Galaxy A-series) بالعربية RTL دون قص أو تداخل ·
الدخول بالبريد والهاتف ينجح · شريط الطوارئ يظهر عند إشارة الخطر · `npm test` و`npm run build` للويب بلا تغيير في النتائج.

### الأسبوع 2 — الميزات الأصلية الأساسية
- [ ] **الجلسة**: رمز التحديث في Keychain/Keystore؛ تسجيل الخروج وحذف الحساب يمسحانه؛ الأدوار الإدارية (2FA) تبقى بلا «تذكّرني» — جلسة تنتهي بإغلاق التطبيق.
- [ ] **تذكير الأذكار محلياً**: نفس شاشة `ReminderWidgets` ونفس الأوقات الثلاثة، جدولة يومية متكررة بتوقيت الجهاز،
      نص عام ثابت (اسم الورد فقط)، النقر يفتح `/ruqyah/...` داخلياً. طلب الإذن عند التفعيل لا عند الفتح الأول.
      Android 13+: `POST_NOTIFICATIONS`؛ Android 12+: `SCHEDULE_EXACT_ALARM` أو قبول دقة ±10 دقائق — **القرار: نافذة غير دقيقة** (لا تحتاج إذناً خاصاً من Play).
- [ ] **دخول Google**: Android عبر Custom Tabs + App Link، والخادم يعيد التوجيه إلى `sanad://auth/callback?code=…` ثم `/auth/google/exchange` الحالي. iOS: الزر مخفي في 1.0.
- [ ] **المشاركة**: صورة الدعاء وروابط المكتبة عبر لوحة المشاركة الأصلية.

**القبول:** إغلاق التطبيق وفتحه بعد 24 ساعة يعيد المستخدم مسجّلاً · إشعار الصباح يصل والتطبيق مغلق والهاتف بلا إنترنت ·
لا يحتوي أي إشعار على بيانات شخصية · الرابط العميق لا يقبل إلا مسارات داخلية.

### الأسبوع 3 — الصوت، الخصوصية، الجودة
- [ ] التلاوة تستمر بقفل الشاشة مع أزرار تشغيل/إيقاف في شاشة القفل.
- [ ] إخفاء المحتوى في مبدّل التطبيقات للمحادثة وملاحظات الحالة والتوصيات.
- [ ] Sentry بإعداد يحذف الأجسام والترويسات والنصوص؛ مراجعة يدوية لعينة أحداث.
- [ ] الأداء: الحزمة الأولى ≤ 300KB gzip (المشاهد المتحركة وSignalR تحميل كسول — موجود جزئياً في `manualChunks`).
- [ ] `prefers-reduced-motion` يوقف مشاهد Framer Motion الثقيلة.
- [ ] CI: وظيفة `mobile` تبني APK وتجري `cap sync` على كل PR؛ إطلاق TestFlight وPlay Internal بوسم `mobile-v*`.

**القبول:** جدول §5 كله أخضر على جهازين حقيقيين (iPhone 12 أو أحدث، وAndroid متوسط بذاكرة 4GB).

### الأسبوع 4 — الإرسال
- [ ] لقطات المتجر بالعربية (6.7" و6.5" لـ iOS، هاتف Android)، الوصف، الكلمات المفتاحية.
- [ ] App Privacy (Apple) وData safety (Google): البريد/الهاتف للحساب فقط، لا تتبّع، لا إعلانات، لا مشاركة مع أطراف ثالثة.
- [ ] تصنيف العمر، وملاحظة للمراجِع: «سند لا تشخّص ولا تعالج — دليل وحجز وإحالة» + حساب تجريبي.
- [ ] تشغيل كامل لـ 23 سيناريو التكامل وPlaywright E2E على الويب، وقائمة اختبار يدوية §6 على الجهازين.
- [ ] إرسال iOS للمراجعة؛ ترقية Android من المغلق إلى الإنتاج بعد انقضاء 14 يوماً.

**القبول:** البناءان مرفوعان، لا ملاحظات حرجة مفتوحة، وخطة رجوع (إصدار سابق جاهز في TestFlight/Play).

## 5. معايير القبول الرقمية (تُقاس قبل الإرسال وبعد الإطلاق)

| المؤشر | الحد | طريقة القياس |
|---|---|---|
| الإقلاع البارد حتى أول شاشة تفاعلية | ≤ 2.0 ث iPhone، ≤ 3.0 ث Android متوسط | Xcode Instruments / Android Vitals |
| التمرير في الدليل والمكتبة | 60 إطاراً بلا تقطيع ظاهر | GPU profiler + فحص بصري |
| حجم التحميل من المتجر | ≤ 40MB | App Store Connect / Play Console |
| وصول تذكير الأذكار | ≥ 99% في نافذته، والتطبيق مغلق | 7 أيام على جهازين |
| الجلسات بلا أعطال | ≥ 99.5% | Sentry / Play Vitals |
| ANR في Android | < 0.47% (حد Google) | Play Vitals |
| التلاوة بقفل الشاشة | 10 دقائق متواصلة بلا انقطاع | يدوي |
| تطابق السلامة | 100% من اختبارات الطوارئ والفلتر تنجح على الجوال | §6 |

**منفذ الخروج إلى Expo:** إن تجاوز مؤشران أو أكثر حدّهما لأربعة أسابيع متتالية بعد الإطلاق، أو رُفض التطبيق مرتين لسبب «تطبيق ويب مغلّف» (Apple 4.2).

## 6. قائمة الاختبار اليدوي الإلزامية (على كل إصدار)
1. نص فيه إشارة خطر في الحجز أو المحادثة ← شريط الطوارئ يظهر فوراً، ورقم الطوارئ يفتح المتصل.
2. مختص يكتب توصية فيها «خذ 500 ملغ» ← رفض برسالة الفلتر.
3. مستفيد لا يصل إلى `CaseNoteEditor` حتى برابط عميق مباشر.
4. حذف الحساب من داخل التطبيق ينجح ويمسح الرمز المخزّن ويلغي التذكيرات المحلية.
5. لا يظهر أي عنصر دفع أو اشتراك في أي شاشة.
6. وضع الطيران: الأذكار والرقية المكتوبة تعمل؛ الشاشات الشبكية تعرض رسالة واضحة لا شاشة بيضاء.
7. تدوير الرمز: رمز وصول منتهٍ ← تجديد صامت مرة واحدة، و429 لا يُخرج المستخدم (ADR-0014).

## 7. المخاطر وطريقة التعامل

| الخطر | الاحتمال | المعالجة |
|---|---|---|
| رفض Apple 4.2 (تطبيق ويب مغلّف) | متوسط | ميزات أصلية حقيقية (إشعارات محلية، صوت بالخلفية، مشاركة، عمل بلا اتصال) + ملاحظة واضحة للمراجِع |
| رفض Apple 4.8 بسبب Google | عالٍ لو بقي الزر | إخفاء Google على iOS في 1.0؛ Sign in with Apple في 1.1 |
| مهلة 14 يوماً في Play | مؤكد للحساب الشخصي | البدء في الأسبوع 1 أو حساب منظمة |
| توقف الصوت بالخلفية في iOS | متوسط | `UIBackgroundModes: audio` أولاً، ثم إضافة صوت أصلية إن فشل |
| انحراف سلوك الويب عن الجوال | منخفض | كل الفروق في `lib/platform` مع اختبارات وحدة لكل تنفيذ |
| تسرب بيانات حساسة في تقارير الأعطال | منخفض | `beforeSend` يحذف الأجسام والنصوص + مراجعة يدوية |

## 8. ما بعد الإطلاق (1.1 — أسبوعان)
- Sign in with Apple، وإظهار Google على iOS.
- إشعارات الخادم الأصلية (FCM/APNs) للرسائل وتحديثات الحجز — ADR جديد يحدّث ADR-0009، بنص عام بلا بيانات.
- قفل التطبيق بالبصمة/الوجه (اختياري للمستخدم).
- تحديثات فورية للواجهة (Capgo/Appflow) فقط إن احتجنا إصلاحات أسرع من دورة المراجعة.
